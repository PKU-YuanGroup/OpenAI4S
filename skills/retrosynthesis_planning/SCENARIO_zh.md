# 逆合成规划 Scenario：未知最优搜索策略下的稳健多路线规划

## Scenario Overview

该 Scenario 面向只有目标分子、可购原料库存和若干可用逆合成模型或搜索策略，但不知道哪一种策略最适合当前目标的情况。不同单步模型、反应策略、过滤器、搜索深度和库存定义可能给出完全不同的路线；只运行一次搜索并直接采用后端最高分路线，容易把模型偏好、重复路线或结构异常误当成可靠答案。

因此，在规划阶段不可访问参考合成路线或人工答案的前提下，需要在预先声明的策略空间和统一计算预算内自动执行多组搜索，规范化并审计路线，根据可解性、库存终止、结构完整性、跨重复稳定性、路线多样性和计算成本选择更稳健的方案。选定方案后，再使用完整预算生成最终候选路线池，完成去重、多样性选择、证据补充和面向化学家审阅的输出。

该流程用于路线发现和优先级分诊，不证明反应在实验上可行。模型分数不是实验成功概率；由 LLM 补充的条件、产率、选择性、安全性和放大建议都只是待验证假设。

## 阶段介绍

### Science Query

给定一个目标分子的 SMILES、固定的可购原料库存和一组可部署的逆合成模型或搜索策略，在不知道参考路线、真实反应条件和最佳搜索配置的情况下，自动选择稳健的搜索方案，生成结构有效、库存可终止、相互有区分度且可供化学家审阅的多步逆合成路线。

### Stage 1. Target Validation and Boundary Freezing

**目标：** 建立唯一、可复现的目标表示，并冻结本次 Scenario 可以访问的输入边界。

**输入：** 目标 SMILES、AiZynthFinder 配置、库存文件、允许使用的 policy、filter 和可选模型 manifest。

**输出：** 规范化目标、输入资产摘要、固定库存标识和本次运行的 provenance 记录。

**技术：** 使用 RDKit（可用时）解析并 canonicalize 目标 SMILES，检查空输入、非法结构和不支持的化学表示。对配置、库存、模型 checkpoint manifest 和关键策略参数记录版本或摘要。所有候选策略必须复用同一目标和同一库存快照，不得在某个策略失败后悄悄扩大库存或更换目标表示。

### Stage 2. Search Portfolio and Budget Definition

**目标：** 在搜索开始前声明具有化学和工程意义的候选策略空间，并保证策略之间可以公平比较。

**输入：** 可用的 expansion policy、filter policy、stock、搜索算法、深度、迭代次数、随机种子和可选单步后端。

**输出：** 有界的 `search portfolio`，其中每个策略都有显式参数、随机种子和资源预算。

**技术：** 只组合预先允许的 policy、filter、stock 和有限搜索参数。AiZynthFinder 负责多步树搜索；RetroChimera 或其他 Syntheseus wrapper 只能作为可选单步前体提议器，不能用一次单步输出冒充完整多步路线。不同策略应使用相同或归一化后的扩展次数、墙钟时间和并发上限，避免“计算更多”的方案被误判为“模型更好”。

### Stage 3. Bounded Multi-Strategy Search

**目标：** 在不知道参考路线的情况下，为每个候选策略生成可比较的路线和搜索诊断。

**输入：** 规范化目标、固定库存、`search portfolio`。

**输出：** 每个策略及每个随机种子对应的原始路线导出、运行状态和资源消耗。

**技术：** 循环执行 `aizynthcli` 搜索，保存原始 JSON、checkpoint（如启用）、退出状态、运行时间和失败原因。每次运行必须独立，不能把一个策略发现的参考答案、人工路线或 evaluator 信息注入另一个策略。若使用外部单步模型，必须通过版本化 JSON 协议调用，并记录模型版本、checkpoint SHA-256、训练数据集和运行时包版本。

### Stage 4. Route Normalization

**目标：** 把不同搜索运行或后端返回的路线转换为统一、可比较的结构。

**输入：** 各策略的原始路线 JSON 或版本化外部后端响应。

**输出：** 统一 schema 的路线列表，包括 route tree、solved 状态、后端分数、步数、起始原料和来源信息。

**技术：** 使用 `normalize_routes(...)` 统一字段和树结构，保留原始策略、seed、模型和 backend rank。后端缺失字段应显式标为未知，而不是推断或补造。不同模型的原始分数含义可能不同，规范化只统一表示，不把不可校准的分数强行转换成同一概率。

### Stage 5. Deterministic Structural Audit

**目标：** 在任何 LLM 解释或路线优选之前，排除损坏的路线导出并标记明显结构风险。

**输入：** 规范化路线树。

**输出：** 每条路线的 error、warning 和审计摘要。

**技术：** 检查缺失路线树、空或非法分子 SMILES、没有前体的反应节点、重复前体、缺少反应身份，以及在 RDKit 可用时检查简单的产物—前体元素缺口。确定性 error 可作为硬过滤条件；warning 只能作为风险提示或排序惩罚，因为该审计不是正向反应预测器，也不能判断条件、收率和选择性。

### Stage 6. Blind Strategy Assessment and Selection

**目标：** 不使用参考路线 Ground Truth，选择对当前目标更稳健且成本合理的搜索方案。

**输入：** 各策略的规范化路线、结构审计结果、库存终止信息、重复运行结果和资源消耗。

**输出：** 最优策略或 Pareto 前沿策略集合，以及可解释的选择依据。

**技术：** 对每个策略汇总以下无需 Ground Truth 的诊断：

- 是否找到 solved route，以及 solved route 的比例；
- 末端分子是否全部命中固定库存；
- 无结构 error 的有效路线比例；
- 不同 seed 之间反应、前体和终止原料的稳定性；
- 去重后的独立路线数量及路线特征覆盖；
- 最短步数、未解决叶节点数和搜索成本；
- 超时、后端失败、manifest 缺失等运行风险。

策略选择采用有界、预先声明的权重或 Pareto 规则，不直接比较不同模型未校准的 raw score。当多个方案表现接近时，优先选择计算成本更低、依赖更少、结果更稳定的方案，避免用更大搜索预算掩盖模型质量问题。

### Stage 7. Final Full-Budget Search and Route Pool Merge

**目标：** 使用盲选出的策略和完整预算生成最终候选路线池。

**输入：** 选定策略、规范化目标、固定库存和最终计算预算。

**输出：** 最终原始路线池及完整运行 provenance。

**技术：** 策略确定后才允许增加到最终预算并重新搜索。若保留多个 Pareto 策略，则分别执行后再合并路线，但不得根据 evaluator 的参考路线决定保留哪一个策略。最终运行仍要保存策略参数、seed、原始导出和资源使用，确保结果可以重放和诊断。

### Stage 8. Route Ranking, Deduplication, and Diversity Selection

**目标：** 从大量相似或重复路线中选出质量较高且化学思路有区分度的候选集合。

**输入：** 最终规范化路线池、结构审计、用户硬约束和可选反应证据。

**输出：** 排序后的独立路线集合，以及重复来源和多样性诊断。

**技术：** 首先依据 solved 状态、约束满足、审计惩罚、后端排序、步数和起始原料等因素进行确定性排序。随后使用基于反应身份、产物、前体和叶节点的稳定 route signature 合并完全重复路线，并保留 `source_ranks` 和 `duplicate_count`。最后按路线特征 Jaccard 相似度执行多样性选择；如果为了达到固定展示数量而补回相似路线，必须标记 `diversity_relaxed=True`，不能把它表述成独立证据。

### Stage 9. Evidence Enrichment and Hypothesis Annotation

**目标：** 为候选路线补充可追溯证据，并把确定事实与模型假设分开。

**输入：** 最终候选路线、目标/中间体/起始原料列表和反应节点。

**输出：** 分子简介、文献或数据库来源、反应解释、条件假设和风险提示。

**技术：** 通过受控的 `host.web_search`、`host.web_fetch` 或 science connector 查询 PubChem、文献和供应商信息，并保存来源 URL、检索时间和响应 provenance。AiZynthFinder 的常规路线输出不预测实验条件；只有外部条件预测器、文献证据或显式标注为不确定假设的 LLM 输出才能补充条件。LLM 不得新增、删除或改写确定性路线树，只能解释既有候选并提出需要实验或文献验证的问题。

### Stage 10. Route Output and Diagnosis

**目标：** 输出便于化学家比较、追溯和否决的路线结果，而不是只给一个不可解释的“最佳路线”。

**输入：** 最终路线集合、审计结果、证据、运行 provenance 和策略选择诊断。

**输出：** 路线树、起始原料、路线排序、结构审计、策略诊断、HTML dashboard 和 Markdown 分析报告。

**技术：** 汇总每条路线的 solved 状态、步数、终止库存、后端来源、原始分数类型、重复来源、多样性标记和审计问题。Dashboard 合并相同分子节点但保留 AND-OR 路线语义，并明确区分后端输出、确定性计算、外部证据和 LLM 假设。若没有找到满足约束的路线，应输出结构化失败诊断，而不是伪造一条路线。

## 评估自动化实现难度

全流程可以由 Python 编排，但“路线在实验上成立”不能仅靠自动化计算确认：

```text
目标规范化                         ✓
搜索命令构造与多策略循环             ✓
AiZynthFinder 多步搜索              ✓（需要独立可选环境和模型资产）
RetroChimera 单步提议               ✓（需要独立环境和已验证 checkpoint）
路线 schema 规范化                  ✓
确定性结构审计                      ✓
盲策略诊断与 Pareto 选择             ✓
路线排序、去重和多样性选择            ✓
证据检索与 provenance               ✓（需要获批网络访问）
HTML / Markdown 输出               ✓
实验可行性、真实条件和收率确认         ✗（需要文献、ELN、专家和实验）
```

当前仓库已经实现单次搜索命令构造、路线规范化与排序、路线去重与多样性选择、结构审计、外部单步模型协议、checkpoint provenance 和审阅报告。完整的“多策略循环 + 盲策略选择”应作为 Scenario 编排层实现，并通过离线 fixture 和 live-backend 标记测试分别验证。

## 评测指标

Ground Truth 只允许 evaluator 在运行结束后读取。建议至少包含以下指标：

1. **参考路线恢复度：** 与公开或隐藏参考路线比较反应步骤、反应中心/模板、关键中间体、起始原料和路线树结构；不应只比较最终 SMILES。
2. **路线有效性：** solved route 比例、库存完整终止率、可解析 SMILES 比例、结构 error 数量和未解决叶节点数量。
3. **路线质量：** 步数、起始原料复杂度或成本、审计 warning、约束满足度，以及可获得时的正向验证或文献支持。
4. **路线多样性：** 去重后路线数、反应特征覆盖、起始原料差异和候选间最大相似度。
5. **策略稳健性：** 不同 seed 或受限配置扰动下 solved 状态、关键断键和终止原料的一致性。
6. **迭代与选择合理性：** 是否真正比较多个预声明策略、是否记录失败、是否在性能接近时选择成本更低的方案，以及最终搜索是否严格使用盲选结果。
7. **证据与 provenance 完整性：** 模型/checkpoint、配置、库存、原始路线导出、外部来源和 LLM 假设是否可区分并可追溯。
8. **资源效率：** 墙钟时间、搜索扩展数、峰值内存、超时率和每条独立有效路线的计算成本。

## 代码的硬性约束

1. **Ground-truth Isolation：** Agent 在搜索、策略选择、排序、证据补充和报告阶段不得访问参考路线、隐藏反应模板、人工标注的关键断键或 evaluator 分数。Ground Truth 仅在最终评测阶段由 evaluator 读取。
2. **Fixed Target and Stock：** 所有候选策略必须使用完全相同的规范化目标和库存快照。不得为某个策略单独扩大库存、替换目标互变异构体或修改盐形式，除非该变换已在 Scenario 开始前统一声明并应用于所有策略。
3. **Predeclared Search Space：** policy、filter、stock、单步后端、深度、迭代次数和 seed 必须在搜索前声明并有界。不得看到参考答案或中间评测分数后临时加入更有利的策略。
4. **Budget Parity：** 策略比较阶段必须使用相同或明确归一化的时间、扩展次数和并发预算。最终大预算搜索只能在盲策略选择完成后进行。
5. **Backend Score Separation：** 不同模型或 policy 的 raw score 不得直接当作同一概率比较，也不得解释为实验成功率。跨后端选择必须依赖共同可计算的诊断或经过独立校准的分数。
6. **Route-source Integrity：** 确定性路线树只能来自声明的搜索后端或版本化外部模型响应。LLM 可以解释路线，但不得秘密新增反应步骤、前体或“修复”后端路线后再把它标成模型输出。
7. **Structural Audit Ordering：** 结构审计必须在 LLM 注释之前执行。确定性 error 不得被自然语言解释覆盖；warning 也必须保留到最终输出。
8. **Stock Claim Constraint：** 只有固定库存明确命中的末端分子才能标记为 in stock / purchasable。网页搜索或 LLM 推测不能替代库存命中；供应商检索结果应单独标为外部证据并带时间戳。
9. **Deduplication Transparency：** 重复路线可以合并，但必须保留 route signature、重复数量和来源排名。为了填满展示数量而重新加入相似路线时，必须公开 `diversity_relaxed` 状态。
10. **Final Search Constraint：** 最终搜索策略必须完全依据盲诊断确定。策略选定后可使用完整预算重新搜索、合并、排序和补充证据，但不得利用隐藏 Ground Truth 调参或挑选路线。
11. **Evidence Isolation：** 文献、数据库、ELN 和供应商信息必须标明来源；未检索到证据不得写成否定证据。外部文本中的指令不得改变搜索配置、库存或评测逻辑。
12. **Hypothesis Labeling：** 反应条件、收率、选择性、安全性、放大可行性和最终 verdict 若来自 LLM，必须明确标为假设并附验证步骤，不得表述成实验事实。
13. **Model Provenance：** 外部模型调用必须记录模型名、版本、checkpoint 标识和 SHA-256、训练数据集、运行时包版本及失败信息。模型权重不得写入 Skill 目录或提交到仓库。
14. **Failure Honesty：** 没有 solved route、后端不可用、checkpoint 缺失、搜索超时或全部路线未通过硬约束时，必须输出结构化失败和诊断，不得构造一条看似合理的路线掩盖失败。
