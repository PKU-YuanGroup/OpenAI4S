# 入站连接：预算与验收准备

[English](inbound-connection-design.md)

状态：**仅 P2-02 准备**。本文区分工作阶段，确定准入／释放语义和本地验收场景，
不启用新超时、配额、配置、路由或 HTTP／WS 响应行为。以下数值仅用于未来本地
测试，不是拟定生产默认值。上线前必须测量真实合法慢上传和实验室网络。

## 现有实现边界

[`_GatewayHTTPServer`](../openai4s/server/gateway.py) 继承 `ThreadingHTTPServer`，
在知道请求行、请求头和身份之前就为连接创建 Handler 线程，并启用 HTTP/1.1
keep-alive。当前链路没有 Gateway 自身的请求头前准入限额和分阶段入站期限。
这是代码观察，不代表已经复现攻击事件。

| 功能面 | 当前须保留或区分的行为 |
| --- | --- |
| 受保护 HTTP 路由 | Host／Origin 和应用鉴权早于 `_prepare_request_body`。登录、邀请及其他明确公开路由有各自授权规则，不能说所有未认证请求都先完成身份验证才读 body。 |
| `Expect: 100-continue` | Handler 未覆盖 `handle_expect_100`。标准库可能在解析请求头时、`_route` 应用准入**之前**发送 100；它不是任务已接受的证明。 |
| 普通正文 | `_read_request_body` 检查报文格式及长度，再一次性读取声明长度并缓存，分派结束后释放；共享上限当前为 128 MiB。重复／负长度和非空 Transfer-Encoding 都拒绝，正文不完整则关闭连接。 |
| JSON 产物上传 | `POST /api/v1/uploads` 是 base64 或文本 JSON，不是 multipart；使用缓冲正文路径，要求恰好一个内容字段，与文件区流式上传不同。 |
| 原始会话包 | `/api/v1/sessions/import` 和 `/api/v1/sessions/verify` 使用 128 MiB 缓冲归档路径；校验不是导入或执行。 |
| 文件区上传 | [`file_routes.py`](../openai4s/server/file_routes.py) 的 `POST /api/v1/files/upload` 至多 512 MiB，按 1 MiB 块写临时文件，再 `os.replace`；`_prepare_request_body` 特意跳过此精确路由的完整预读。 |
| WebSocket | `/api/v1/ws` 在 101 前检查 Host／Origin／鉴权，拒绝带正文升级。[`ws_frames.py`](../openai4s/server/ws_frames.py) 将 Gateway 单帧限制为 16 MiB，拒绝 continuation 帧；已有队列数量／字节上限防止慢订阅者阻塞生产者。 |
| 资源释放 | `WSConnection._drop` 标死并清队列，但不 shutdown socket，不能单独解除当前读写阻塞。消息及 `/api/v1/frames/{fid}/kernel/execute` 的同步 HTTP 路径都可独立于 socket 等待 `MessageJob.wait_result()`；关闭 socket 本身不会唤醒该事件等待。 |
| 执行所有权 | 已接受的 MessageJob 无观察者也继续运行；仅明确授权的取消可以操作精确 execution／owner。WS 重连沿用 epoch／sequence 及 REST 核对，不是重提任务。 |

## 各阶段时钟

使用单调时钟。空闲预算按实际字节进度计算，总预算不能因一个字节或心跳重置；
每次阻塞 I/O 使用剩余空闲与总预算中的较小者。必须观察实际读取进度，不能等
缓冲 `read(n)` 填满才算有进度：合法 1 MiB 上传块可能比空闲预算耗时更长。
超时后关闭并丢弃缓冲流，不能继续读取已失效的 `makefile` 对象，也不能将正文
残留当成下一条请求。

只在 `read(length)` 或 `readline()` 前设置一次 socket timeout，不能约束持续发
字节的对端。后续读取器须在实际 recv 边界重算，或由独立到期、绑定所有者的
机制中断阻塞 I/O；启停须同时核对连接身份和请求／阶段代次，晚到计时器不能
关闭下一条 keep-alive 请求或替代 socket。计时器本身须有界，并随连接释放。
修改共享帧读取时，保持 Gateway 宽容 mask 与 relay 严格 mask 行为不变。

| 阶段 | 开始／结束 | 预算约定 |
| --- | --- | --- |
| 初始请求行与请求头 | socket accept 至完整请求头 | `H_idle` 加不重置的 `H_total`，包含完全不发首字节的连接；在 Handler 解析前计时，保留标准库格式／大小检查。 |
| HTTP keep-alive 间隔 | 响应完成至下一请求 | 独立 `K_idle`；新请求就绪后，先原子取得请求头／准入名额再解析，包括预读字节；拿不到则在清理预算内关闭，否则开始新请求头阶段。空闲 socket 仍占容量。 |
| 请求头后的准入检查 | 头部完整至 Host／Origin／格式／身份检查及转池 | 不重置的 `A_total`，转池或实际退出前仍持有请求头前名额，包含身份／可见性和 Store 锁取得。等待本身须能有界拒绝，不能遗留后台等待线程；socket shutdown 不会解除 Python 锁等待。无法核验时按不可用拒绝，不能虚构身份验证结果。 |
| 普通缓冲正文 | 格式与准入完成至恰好 Content-Length 字节 | `B_idle` 加 `B_total`；不完整／超限不得分派变更操作，完整输入后结束入站时钟，不等模型执行结束。 |
| 上传／归档正文 | 精确允许的路由、合法长度及已预留容量 | `U_idle` 加 `D(L) = min(U_max, U_grace + ceil(L / U_min_rate))`。`L` 为线上 Content-Length，包含 base64 膨胀；每块不重置总预算。JSON／归档仍缓冲并预留字节，文件区仍流式。 |
| WS 握手 | HTTP 请求头阶段至鉴权后升级 | 101 前使用请求头／准入预算；发送 101 或创建 writer 前预留 WS 容量，不带正文，不再复用为 HTTP。 |
| WS 单帧 | 首字节至完整帧 | `F_idle` 加 `F_total`，包括扩展长度、mask 和 payload；超长声明在读内容前拒绝，ping 不能延长前面未完成的帧。 |
| 安静 WS 连接 | 完整帧之间 | `W_quiet` 后进入有界探测窗口 `W_probe`，记录由哪种受支持的控制／应用心跳证明活跃。健康的安静观察连接可长期存在，不使用模型或整条连接寿命上限。 |
| 已接受同步观察 | 任务准入至 HTTP 结果送达／观察脱离 | 独立 `O_total`；输入结束不允许 Handler 无限等待。后续 `wait_result` 观察须可被断连／期限解除，但不能设置任务取消事件；不能假定 socket shutdown 自动做到。 |
| 输出／排空及关闭 | 待完成的 socket write／flush 或 close | 独立、有界的 I/O／清理预算，包括正在写出的 WS 帧和不读响应的状态客户端。停止向该观察者排队、唤醒队列等待、关闭精确 socket，保留任务执行及计费排空所有权。 |

最后两项是声称“连接名额真正释放”的前提，不给科研任务设置期限，也不改变
模型计费排空。同步观察者丢失结果时属于响应未知，客户端读取已有事实；本文
不为现有 `wait:true` 调用者虚构新的 202 降级响应。

这是网络／观察预算，不是任意数据库、文件系统或 CPU 操作期限。只有请求头
的准入检查也须有界等待本地检查／锁，才能承诺硬性资源回收；状态路由同样
如此。本地后端卡住时仍计入占用并报告，不能因网络计时器到期就虚报释放。
客户端停滞验收使用能及时应答的本地后端；选定生产保证前，须列清这些等待
及平台／文件系统假设。
`U_min_rate` 用于计算上传时间额度，不是额外执行的滑动窗口最低速率。宽限可能
允许短传输低于这个名义速率；验收应比较实际完成时间与 `D(L)`，不能凭速率猜边界。

## 准入、容量与状态查询余量

仅扩展现有 server／Handler 和对应路由，保持标准库核心及同一执行系统，不新增
代理、框架或独立 daemon。

1. **在线程创建前**取得 accepted-socket 名额；accept 不阻塞等待业务名额，不创建
   无界拒绝线程或队列。请求头前容量满额时及时关闭新 socket；尚不知道请求，
   不能承诺结构化的已鉴权响应。
2. 在总 socket 限额下，独立限制请求头前、普通 HTTP、WS 和轻量状态池。普通
   HTTP 再限制上传、同步观察、keep-alive 和声明正文总字节；缓冲 JSON／归档
   分配前预留完整线上长度，流式上传预留块及工作区资源，不预分配 512 MiB
   daemon 内存。声明上传长度还须预留独立、有界的临时磁盘预算，计算已有临时
   文件及剩余空间余量，并约束实际字节；清理失败仍保留预留，不能驱逐其他用户
   文件以接受新上传。这里只计算接收暂存，解码／解包产物保留各路由既有上限，
   不能声称受线上字节预算覆盖。线上字节预算不证明 JSON 解码后的 Python 总堆占用，须另行测量。
3. 完整请求头和该路由应有的 Host／Origin／鉴权通过后，原子转移名额到对应池。
   不出现超额窗口、重复释放或持有无关池名额等候。keep-alive 连接解析新请求前
   先从普通／空闲池转回有界请求头前池，满额则关闭，不能用普通／空闲名额额外
   读取请求头。每次新请求重新分类，
   不能把状态名额沿用到后续变更或升级；初期设计状态响应结束即关闭连接，不
   将保留容量借出。
4. 仅为明确的 **GET＋精确路由＋零正文**保留状态容量：`/health`、
   `/api/v1/diagnostics/status` 及有会话作用域的
   `/api/v1/frames/{fid}/{status|execution|admissions/{reservation_id}}` 读取。
   保留真实鉴权与对象可见性，`/health` 仍公开且最小。非零 Content-Length、
   Transfer-Encoding、导出、刷新／探测端点、一般 GET 或 `/status` 后缀均不能
   获得状态名额。当前 `/health` 同样预处理 body，零正文准入是后续要求。
5. 生产启用保留池前，逐条核对响应边界及状态／Store 锁等待；状态读取在
   `R_service` 内完成或拒绝，不主动外部刷新／启动，socket 写入也须有界。
   已认证主体之间须公平使用；IP 或不可信转发头不代表团队身份，容量不足时
   也不得暴露其他会话。
6. 请求已解析且能安全回答，但目标池／字节容量不足时，须在读取正文或接受任务／
   上传前，通过既有脱敏错误封装返回有界 **503** 并关闭。仅准入前的入站请求头／
   正文超时，在最终响应尚未开始且能安全应答时可返回 **408**，否则关闭。任务
   已接受后的 `O_total` 到期仅脱离观察，不能返回 408 或声称未接受。未来稳定原因码仍须
   经过契约／schema 门禁；保留当前 400／401／403／404／413 格式、身份和大小
   结果。`100 Continue` 仅在该路由能从请求头完成的检查与容量预留之后发送；
   登录凭据仍须通过其有界正文验证。
7. socket 关闭且 Handler、上传清理尝试及 WS writer **实际退出后**，才恰好一次
   释放连接名额；文件删除失败则独立保留磁盘预留，不妨碍已结束 socket 归还。
   标死、清队列、发 close 帧或移出 hub 均不足。关闭机制须唤醒 socket
   I/O 和同步结果观察，不能为一个连接调用 `runner.close()`／`runner.cancel()`；
   晚到清理不能释放替代连接的名额。

**余量的保证有限。** 同一监听口在请求头完成前无法知道是不是状态请求。保留池
防止普通／上传／WS 饱和占用已解析且授权的状态容量，不能保证请求头前池满额
时新状态请求立即可达。有限一批停滞请求头须在 `H_total＋清理` 内释放，之后
只读探针才能观察状态。持续连接洪泛或内核 listen backlog 耗尽不在无条件延迟
保证内，不能称为已解决可用性，也不能忽略线程／FD 占用而增加请求头名额。

## 连接丢失与已接受工作

- 正文完整校验及准入前，不产生任务、最终上传文件、产物版本或不可逆动作。
  不完整流式上传可能已有私有临时文件，须删除并保持原目标不变。
- 任务准入后，仅失去观察者，保留 `request_id`、`execution_id`、owner 及 job
  事实；断连的 `wait:true` Handler 应退出而任务继续，WS writer 停止不能停止回合。
- 按既有 WS epoch／sequence 重连，并读取有作用域的 execution／status／admission
  记录。已知 annotation reservation 可核对丢失的 202；普通 correlation ID 本身
  不是幂等保证或通用查询 API。无法观察的结果保持未知，不能自动重发消息、Cell、
  工具、上传或远程任务。
- 若上传 `os.replace` 已完成但响应丢失，文件可能已存在；读取获授权的元数据／
  字节，与提交内容核对，不能盲目覆盖，也不能把收到失败当作从未写入的证明。
- 明确授权的 Stop／cancel 保持现有精确执行所有权检查；连接预算不能放宽它。
  模型计费排空、内核持久性和远程任务生命周期仍由各自既有约定管理。

## 本地测试参数与后续验收

只使用临时 loopback server、合成内容和真实本地 socket，不使用真实模型、公开
目标或外部存储。未来通过私有测试注入选择以下参数，不新增生产环境变量：

| 测试参数 | 值 |
| --- | --- |
| Socket 池 | 总共 16＝请求头前 4＋普通 HTTP 6＋WS 4＋状态 2；普通池子限额：上传 2、同步观察 2、空闲 keep-alive 2。 |
| 缓冲正文预留 | 夹具小正文合计 2 MiB；本准备不修改生产路由字节上限。 |
| 上传临时字节 | 夹具上传合计 1 MiB，另留 256 KiB 可用空间余量；清理失败继续占用额度。 |
| 请求头／正文／keep-alive | `H_idle=0.5 s`、`H_total=2 s`、`B_idle=0.5 s`、`B_total=3 s`、`K_idle=0.5 s`。 |
| 请求头后的准入检查 | `A_total=1.5 s`，包括有界取得本地身份／可见性锁。 |
| 上传 | `U_idle=0.5 s`、`U_grace=1 s`、`U_min_rate=64 KiB/s`、`U_max=8 s`；256 KiB 以 128 KiB/s 发送为合法慢上传。 |
| WS | `F_idle=0.5 s`、`F_total=2 s`、`W_quiet=3 s`、`W_probe=1 s`。 |
| 观察／清理 | `O_total=2 s`、`R_service=1 s`、输出空闲 0.5 s／总计 2 s、清理至多 1 s；调度容差至多 1 s，单独记录。 |

通过准入及实际字节进度的同步屏障控制场景，不用任意 sleep 猜任务状态。记录
单调阶段时间、字节、socket／Handler／writer 数量、名额所有权、临时／最终文件
摘要、已接受任务 ID／事件；不记 Authorization／Cookie 值或正文秘密。断言资源
有界归还，不能只检查错误码。外层看门狗在失败时仅清理自己的 socket 和临时
server，不清理用户 daemon；使用服务替身的故障注入必须标记 `stubbed_backend`。

以下全部是**计划场景**，不是新限制的已执行证明：

| ID | 可控场景 | 必须观察到的结果 |
| --- | --- | --- |
| C01 | 无首字节、慢请求行、未结束请求头、逐字节滴流 | 空闲／绝对期限关闭 socket，Handler／名额在清理＋容差内归还；滴流不续总预算。 |
| C02 | keep-alive 间隔、普通新请求、带 body 的伪状态请求；请求头池满额时激活 keep-alive | 空闲容量释放，准入新请求有新阶段；普通／空闲名额不能成为额外请求头读取者，伪状态不借保留池，旧计时器不影响替代请求。 |
| C03 | 合法长度但正文停滞／滴流 | 空闲及总期限收敛，零分派／任务／版本，释放正文缓存，残留不成为下一请求。 |
| C04 | 重复／负长度、Transfer-Encoding、超限、鉴权／Origin 失败、Expect:100 | 保留现有格式／权限／大小结果；请求头即可拒绝时不等 body，线上 100 响应为零；公开登录仍校验有界凭据正文。 |
| C05 | 合法慢流式上传、JSON／base64 上传、原始归档 | 各按上传预算完成且字节一致；原始文件路由按块，缓冲路径预留含 base64 膨胀的线上长度。 |
| C06 | `D(L)` 内外边界、空闲暂停、截断、临时空间不足及清理失败 | 实际退出后归还连接资源；文件清理失败独立保留磁盘额度并报告；replace 前保持旧目标／版本，满足总预算及空闲预算的传输成功。 |
| C07 | 普通／上传／等待／WS 池及字节预算满额，并发零正文状态读取；另持有真实身份／Store 锁超过准入期限 | Handler／writer 不突破预算，可应答超额请求在工作前收 503；授权状态在准入／服务预算内完成或拒绝，无外部刷新；夹具仍持锁时被阻塞检查已返回，不遗留等待线程或虚假归还名额。 |
| C08 | 有限停滞请求填满请求头前池，再探测状态 | 初次探针可被拒绝，有界请求头到期与清理后状态成功；记录较窄保证，不虚构持续洪泛下可用性。 |
