# frontend/src/features/send

[中文说明](README_zh.md)

F-11 send chain and live cards. Composer `send()`, turn tickets, step / plan / permission / candidate cards, attachment and @-ref problem cards, and the admission tracker. Window names (`send`, `buildStepCard`, `renderAttachmentProblems`, `renderRefProblems`, `searchResultHttpUrl`, `admissionSettled`, `forgetAdmission`, `outstandingAdmissions`, `reconcileLastAdmission`, `rememberAdmission`) are assigned here, not left as F-05 stubs. `frame_update` stays F-06; the turn-ticket body is injected through `setFrameUpdateTurnHandler`.

| [`permission.ts`](permission.ts) | Permission gate cards. Frozen DOM classes `.perm-card` / `.resolved` / `.allowed` / `.denied`. `permTitle` titles a download, an install and an environment switch from the request's own tool and input in the UI language (feature-local copy; any other kind uses the server's title through the step-title templates), and a language switch says it again; a download card shows the whole URL, the workspace-relative target (`workspaceTarget`: never a local directory) and its size, or the cap it stops at. A card starts at scope `once` (no standing rule unless the user widens it); a widened scope starts from `defaultRememberPattern` -- a shell command's prefix (`python3 -c *`), another tool's exact target, never `*` -- and the rule chips are named for what they cover ("This exact command", "Everything (not recommended)"). A 202 `decision_resolving` (accepted, commit still in flight) keeps the buttons down with a neutral status line (feature-local copy) until `permission_resolved` settles the card. A live card is placed like a step (the prose so far above it, later prose below), and a replayed or re-sent event for a card rendered from history moves it into the running turn. `renderStoredPermission` renders a stored decision (`GET /frames/{fid}/approvals`) where history places it, with its outcome: allowed, denied with the typed reason, timed out or cancelled (feature-local copy); a pending one stays answerable. A language switch relabels every card in place: fixed labels carry `data-i18n` for the static repaint (an open card keeps what was typed), and `relabelPermissionCards` restates decided outcomes. `reconcilePermissionCards` settles cards still shown as open from those stored decisions after every subscription replay, and when an Allow/Deny answers `decision_already_resolved`/`decision_expired` (decided in another tab while this one was away). |
