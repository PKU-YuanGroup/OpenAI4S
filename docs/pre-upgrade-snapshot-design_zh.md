# 预升级数据库快照：设计与验收准备

[English](pre-upgrade-snapshot-design.md)

状态：**仅 P2-01 准备**。本文确定后续保留策略与验收用例，不启用快照、不新增
命令或配置、不修改 schema 32、迁移或恢复行为。以下用例是未来实现的要求，
不是已经通过的测试。

## 当前边界

[`run_migrations`](../openai4s/storage/migrations.py) 先检查完整性，再使用 SQLite
备份 API 创建 `<数据库>.v<版本>.bak`，并在显式事务内执行编号迁移。失败保留
备份，成功后尝试删除（unlink 失败被忽略）；现有 `test_successful_migration_cleans_up_its_backup` 继续约束
这一清理行为。当前版本数据库走不迁移的快速路径；`FutureSchemaError` 拒绝
较新 schema，不能降低其版本号。

当前备份并非全部应用初始化之前的快照：
[`Store.__init__`](../openai4s/store.py) 先执行并提交 `_SCHEMA`，再调用 `_migrate`。
后续保留快照必须放在应用 DDL、种子数据及数据变换之前，并保留两次 schema
检查。只复用当前较晚的备份位置不符合本设计。SQLite 重放热回滚日志是在恢复
已提交状态，与应用迁移不同；备份也必须包含已提交的 WAL 状态。
`preflight_schema` 返回 `None` 既可能是文件不存在，也可能是只读连接不能
恢复热日志，不能据此跳过已有数据库。不得用 `immutable=1` 或只读主文件头绕过
识别 WAL 的 schema 检查。恢复可能改变源字节，但保留已提交逻辑状态。若另有
原始取证字节保全要求，应在恢复前保留停写后的完整 DB／journal／WAL 文件组。

[`security/permissions.py`](../openai4s/security/permissions.py) 的权限加固及目录
fsync 目前均为尽力而为，不能证明以下严格权限与发布约定。原生 Windows 目前
被平台门禁拒绝，本文不扩展平台支持。

## 保留策略

| 决策 | 后续约定 |
| --- | --- |
| 触发 | 仅在显式升级已有、非空的配置数据库 `openai4s.db`，且目标为更高的受支持 schema 时触发。首次创建、当前 schema 打开和未来 schema 拒绝均不新建或替换保留快照。 |
| 写入所有权 | 停止 daemon 以及能写该数据目录的 CLI、Jupyter 等进程，并在快照发布至迁移结束期间持有独占升级所有权。仅凭 daemon pidfile 不足以证明独占；无法建立所有权则拒绝升级。 |
| 位置 | `<data_dir>/backups/pre-upgrade/`；不放入工作区、产物目录、公开路由、导出包或自动远端副本；不静默跟随重定位或符号链接。 |
| 布局 | `current.json` 指向一个不可变 `snapshot-<随机 ID>/`，其中只有 `database.sqlite3` 与 `manifest.json`。同一文件系统内的候选目录明确命名为 `.pending-<随机 ID>`。这些是拟定路径，当前 OpenAI4S 不创建它们。 |
| 保留份数 | 稳态只选定一份已校验的最近**预升级**快照，保留至下一份通过校验后替换，或由所有者明确删除。不按年龄过期，不拿升级后副本代替；迁移失败同样保留。 |
| 临时副本 | 替换期间至多同时存在旧选定代与一份新候选／已发布代。崩溃可能留下两份，但仅由 `current.json` 指明选定项；清理完成前不开始另一份候选。 |
| 权限 | POSIX 目录 `0700`、文件 `0600`，从创建时即属于升级账户；拒绝异常符号链接、硬链接、所有者变化、宽松 ACL 或可被他人写入的父路径边界。临时文件与 sidecar 同样检查，不能出现短暂公开可读窗口。 |
| 不受支持的存储 | 无法验证仅所有者访问、同文件系统原子替换或持久发布时，拒绝创建受管理快照并保留旧副本；如实指出未满足的属性，不能把尽力 chmod/fsync 当作证明。其他平台须另行验证 ACL 与持久性后才可接入。 |
| 敏感性 | 整个 SQLite 镜像可能包含研究历史、遗留明文凭据、授权记录和秘密引用；不能删敏后仍称其可恢复。清单及验收收据保持私有；日志不写凭据值、数据行或数据库字节。 |

选定快照是恢复余地，不是长期归档或加密备份。删除旧代只删除路径名称，不能
承诺 SSD、文件系统快照或外部备份中的安全擦除。

## 容量与校验

本准备策略确定：**单个数据库镜像上限 4 GiB，替换期受管理目录上限 8 GiB 加
1 MiB**；每份清单至多 256 KiB，每份指针至多 4 KiB，旧／新清单与临时指针
都计入 1 MiB 元数据总限额。这些是未来策略值，
不是新增运行时配置。更大数据库需要单独审查策略，不能先删旧有效快照腾空间。

停止写入并恢复已提交状态后，设 `S = page_count * page_size`，
`R = max(64 MiB, ceil(S / 10))`。预检要求 `S <= 4 GiB`、可用空间至少 `S + R`，
并确认现存选定镜像、新镜像及有界元数据满足目录总限额。实际用量须计算遗留
候选，不能忽略异常文件。复制期间继续检查可用空间和实际写入字节，因为预检
不是空间预留。ENOSPC、配额不足或实际镜像超限都应终止候选，保留旧选择与源库
已提交数据。

受管理目录外已有的 `<数据库>.vN.bak` 属于独立的遗留失败备份；在文件系统
可用空间检查中计入其占用并单独报告，不得为满足新策略而静默删除或收编。
后续集成应复用已验证的预升级镜像来满足编号迁移的备份要求，不能额外创建
未计入容量的 `.bak` 副本。本版本不改变当前备份行为。

这里只预留快照空间。后续迁移及回滚日志的空间必须按具体迁移另行估算，`R`
不能保证任意 DDL 或数据扩展都能完成。本地验收通过注入字节／剩余空间限制
覆盖边界，不要求 CI 真分配数 GiB。

使用 SQLite 备份 API 在私有候选目录构建镜像，不能复制打开中的主库却遗漏
WAL／journal。关闭目标连接后，另开只读连接独立校验，必须同时满足：

- 镜像为自包含普通文件，不依赖 WAL、SHM 或热日志；完整执行
  `PRAGMA integrity_check`，结果恰为成功结果。
- `PRAGMA user_version` 等于本次读取的源版本，不能是预期升级目标版本；保留
  并核对已有迁移记录。未编号遗留库可以确实没有迁移记录表。
- 实际长度和流式 SHA-256 与有界清单一致，发布后重新打开、重新计算。
  校验和能发现字节变化，不能抵御同时替换私有清单与镜像的攻击者。
- 清单结构包含格式版本、快照 ID、UTC 时间、源应用构建身份、源／目标 schema、
  相对数据库名、长度、摘要和校验结论；无法取得的源构建身份明确记为未知。
  指针仅含选定代 ID 与清单摘要；文件名和相对路径拒绝穿越及身份歧义。

## 发布、失败与继续

1. 应用写入前建立独占所有权并核对受支持 schema；校验已有选定镜像、处理有界
   遗留项。指针或旧镜像无效属于明确恢复问题，不能当作从无历史。
2. 预检权限与容量，创建一份私有候选、备份、关闭 SQLite 并完成上述独立校验。
   全程保持旧选择不变。
3. 对镜像、清单及包含其名称的候选目录依次 fsync；以原子改名发布不可变代，
   再 fsync 受管理父目录。重新打开、校验后才准备新的有界指针文件。
4. 刷新新指针，原子替换 `current.json`，持久化父目录项，再读取选择并校验
   对应清单／镜像。仅此时算新快照提交成功。指针替换后的任何错误属于**发布结果
   不确定**：指针可能已指向新代。保留两代，不开始迁移，要求独占恢复；不能声称
   旧指针未变，也不能静默回选。
5. 仅在第 4 步成功后删除被替换的旧代。清理失败则保留旧文件、记录清理待办，
   并在移除未选定旧代、仅剩一代前拒绝另一份候选。不得删除选定镜像；发布中断不授权未经
   校验的清理。
6. 快照成功发布后才能开始应用升级。无论迁移提交或回滚，都保留快照；保持原有
   事务迁移与未来 schema 保护，不能向仍有连接打开的数据库覆盖备份。

重启后，在独占所有权内检查路径、身份、指针、摘要及权限。指针发布前以旧代
为准，持久发布后以新代为准。完全校验但尚未选定的候选不能仅因 mtime 更新
而被选中；须明确核对或仅丢弃该未选定候选。断电造成发布持久性不确定时，
删除任一代前必须重新验证。选定代校验通过则补完持久发布；否则报告无效／不确定
选择，要求明确修复为另一份单独校验的代，不恢复迁移、不凭目录 mtime 推断旧指针。
重复尝试不能堆积快照，也不能用固定 `.bak` 路径
覆盖唯一有效副本。

## 独立目录恢复约定

恢复由运维人员明确控制、离线进行；不是自动迁移回滚，本轮不提供原地恢复命令。

1. 停止源安装的所有写入者，保持源目录及选定快照不变。记录快照／构建／schema
   身份，并检查私有副本的完整性、长度、摘要与权限。
2. 在容量足够的存储上创建仅归操作者所有的全新同级数据目录。拒绝已存在或非空
   目标、源目录内部的目标、符号链接及与源别名重合的目标。将关闭且自包含的
   镜像复制为新的 `openai4s.db`；不能合并目标 WAL／journal，不复制源 pidfile
   或访问令牌。
3. 启动应用前，使用只读 SQLite 再次检查恢复镜像，并在验收中核对已知夹具行
   和迁移记录。不打开 `Store`，因为构造器会初始化和迁移数据库。选定快照
   必须保持字节一致。
4. 恢复目录保持离线用于检查。单独的应用试运行仅在可丢弃的**合成数据**目录
   中，以兼容程序、禁出网、无继承凭据、无活动调度器／relay／内核／远程轮询／
   自动恢复的条件进行。不能假定当前已有通用“安全恢复启动”开关。真实恢复
   数据中的绝对路径、身份、存储授权与任务状态未独立复核前不得启动服务。
5. 后续若决定启用恢复安装，须按当前外部事实核对凭据、授权与任务。保留已记录
   事实，不能因为旧 DB 中有记录就自动重放 Cell、重试工具、提交／取消远程工作
   或恢复旧审批。程序拒绝较新 schema 时仍应拒绝，不能降低 `user_version`、
   删除迁移记录或绕过 `FutureSchemaError`。

数据库包含元数据和引用，**不包含**完整工作区、不可变产物字节／CAS、Python／R
内存、环境与包、钥匙串／环境注入凭据、远程作业及外部副作用；部分路径还是
绝对路径。换一个数据目录本身不能隔离这些引用，也不能把旧任务记录变成当前
远程事实。缺失文件、环境及凭据保持不可用，旧链接不能静默指向无关的新文件。
DB 恢复不等于完整工作区恢复、凭据回滚或一键应用降级。

## 后续本地验收矩阵

以下全部为**待实现的计划用例**，使用合成数据及独立临时目录，扩展现有迁移
测试与本地恢复夹具，不要求真实用户数据、模型调用或新 CI 服务。

| ID | 可控场景 | 必须观察到的结果 |
| --- | --- | --- |
| S01 | 新建库、当前 schema、未来 schema | 不替换保留快照；未来 schema 在应用写入前拒绝，版本不变。 |
| S02 | 旧真实 schema，含当前 `_SCHEMA` 新增表的差别 | 选定快照等于应用初始化前源库，不含后加表，保留源行及迁移记录；迁移成功后仍保留。 |
| S03 | 已提交 WAL、崩溃产生的热回滚日志 | 包含已提交行、排除回滚行；preflight 返回 `None` 不跳过已有 DB；恢复镜像自包含，只读完整性通过；区分源逻辑状态保留与恢复字节变化。 |
| S04 | 指针替换前：旧有效快照，加注入 ENOSPC、字节超限、权限、复制、完整性或摘要失败 | 旧选择／摘要／字节不变，不开始迁移，有界私有候选清理，明确失败。 |
| S05 | 在复制、flush、rename、指针、清理边界杀进程；指针替换后校验或 fsync 失败 | 发布不确定则保留两代，独占恢复验证选定代或明确修复选择前不迁移、不删除；不删除唯一有效副本、不凭 mtime 猜测，遵守两代限制。 |
| S06 | 新快照已校验后迁移失败 | 活库回滚，预升级镜像保留，不覆盖打开的 DB，不自动恢复或重放。 |
| S07 | 升级进程竞争、遗留所有权 | 至多一个发布／迁移者；旧 pid 不能授予所有权，败者不改变 DB 或快照身份。 |
| S08 | 宽松模式／ACL、符号链接、硬链接、所有者变化、不支持持久化 | 在暴露或迁移前拒绝创建／发布，保留旧副本；分别验收 POSIX/macOS/Linux，其他平台仍为未验证。 |
| S09 | 恢复到新目录，再改动可丢弃恢复副本 | 初始行／schema／摘要正确，选定镜像及源目录不变；已有、非空、别名目标拒绝。 |
| S10 | 截断／损坏镜像、坏指针／清单、合法遗留库无迁移表 | 损坏与身份不符拒绝；显式处理合法 version-0，不虚构迁移记录。 |
| S11 | 缺 CAS／工作区／环境／凭据，但有远程及恢复工作记录 | 只读检查如实显示缺失边界；夹具观察到零 Cell／工具执行、网络调用、任务重提和审批复活。 |
| S12 | 容量边界、遗留 `.bak`、多次升级／重启 | 预检和实际写入上限都生效，不能驱逐旧有效副本腾空间；遗留备份单独报告且不自动删除；稳态一个选择，恢复期最多两代。 |

本次准备完成意味着策略、失败状态与可观察矩阵已明确，现有迁移测试仍通过。
后续运行时完成还须在真正实现上执行 S01–S12 并记录文件系统／平台限制；
本文不能代替那一轮验收。
