# frontend/src/features/onboarding

[中文说明](README_zh.md)

M-01 first-run wizard kernel. Four required decision steps, skip, and B-04 `capability_receipt` badge rows. GET `/onboarding` is redacted and contacts nobody; Test is the only action that probes a provider.

## Files

| File | Responsibility |
| --- | --- |
| [`api.test.ts`](api.test.ts) | Existing-profile activation occurs before onboarding status refresh; endpoint model discovery returns the served protocol default (else the first id) and surfaces a failure as the thrown `ApiError`. |
| [`api.ts`](api.ts) | `GET /onboarding`, `POST /onboarding/complete`, profile save/update/activate/probe. |
| [`badges.test.ts`](badges.test.ts) | Tri-state badge rows and the pills `CapabilityBadges` renders from them; unknown reason is not rewritten. |
| [`badges.ts`](badges.ts) | `capability_receipt` → `true` / `false` / `unknown` rows + stale. The tri-state word follows the UI language (支持 / 不支持 / 未确定). |
| [`boot.ts`](boot.ts) | `bootOnboarding()` loads and mounts the wizard (`#onboarding-root`) only when setup is not complete, its status cannot be read, or this tab's wizard left a resume marker the status still vouches for (`startOnboarding`, NV-04). |
| [`boot.test.ts`](boot.test.ts) | The wizard chunk is not loaded for a completed setup; it is for one still to do, for an unreadable status, and for a reload after this tab saved a profile (active or not). A finished/skipped setup, a missing profile or a daemon without `completed_explicitly` clears the marker and keeps it closed. |
| [`copy.ts`](copy.ts) | Lane-local zh/en strings (`ot`). Does not rewrite generated i18n. `copyLookup(table)` is the lookup `ot` and `judgmentT` share. |
| [`copy.test.ts`](copy.test.ts) | `copyLookup`: active language, then English, then the key; the loaded dictionary wins; positional holes. `ot` and `judgmentT` are built on it. |
| [`index.ts`](index.ts) | Public re-exports. |
| [`machine.test.ts`](machine.test.ts) | Skip / step-rail jumps / request-id errors; providerRequests=0 before Test, and a model-list fetch counts without deciding Test; model identity changes clear receipts and Test decisions; a probe result measured for another profile is dropped. NV-04: the resume marker holds only `{step, profile_id}`, drops any other shape, is a no-op where storage is refused, and `resolveResume` returns to Test only for the active saved profile, offers the path step for an unactivated one, and clears it otherwise; `resume` starts a fresh wizard with no request counted. |
| [`machine.ts`](machine.ts) | Four-step reducer. Model identity changes clear the prior capability receipt and Test decision; display-only changes preserve them. A `testResult` names the profile it measured and is ignored unless that is the selected path. Credentials never enter wizard state. NV-04: the same-tab resume marker (sessionStorage, `{step, profile_id}` only) and `resolveResume`, which checks it against the authenticated profile list and `completed_explicitly`. |
| [`mount.ts`](mount.ts) | `mountOnboarding()`: renders `WizardHost` into `#onboarding-root`. The only importer of the wizard UI, so the build keeps it out of the first-load bundle. |
| [`presets.ts`](presets.ts) | Provider presets for the wizard's cloud form: `readProviderPresets` reads `provider_presets` from `GET /onboarding` (the registry's endpoint and default model per protocol), `presetLabel` names a provider, and `keyPage` gives the page a key comes from only where `docs/startup-guide.md` names one. No URL is made up in the UI. |
| [`status.ts`](status.ts) | Sanitize GET payload; drop credential-shaped keys. `completed_explicitly` is a boolean, or `null` for a daemon that predates it. |
| [`wizard-integration.test.ts`](wizard-integration.test.ts) | Existing-profile Continue awaits activation and refreshes edited model identities before dispatching the next step. Readiness refresh keeps the step/path/receipt/providerRequests and lets only the newest of two local reads shape the four status fields. NV-04: a new user who saves and reloads is back at Test with the profile listed once and no probe before the click; an unactivated profile is offered on the path step; walking on keeps the marker and Skip or finishing clears it; a configured install, a completed setup, a missing profile, an old daemon and refused storage keep the original flow. |
| [`wizard-cloud-form.test.ts`](wizard-cloud-form.test.ts) | FR-2: the wizard opens on the cloud form when no model is configured; the API key comes before the model; providers are offered by name with the registry's endpoint and a documented key page (words, not a link, where the docs name none); the missing-name message sits under the name field; the modal carries a language switch and no second list of the steps. |
| [`wizard-save.test.ts`](wizard-save.test.ts) | Saving a new profile or activating an existing one re-reads the composer's model list. Continue on a path already saved updates that profile (the key is kept when the field is empty); an identical saved profile is reused; one deleted meanwhile is saved afresh. Continue with an empty model saves the protocol default the endpoint serves, never after a failed fetch or for an endpoint edited meanwhile, stays disabled while the fetch runs, and saves the name typed meanwhile. The model configured by environment variables is offered (only while no saved profile stands for it), is saved keyless and activated on Continue, and is what Test measures when nothing else is chosen. |
| [`wizard-skip.test.ts`](wizard-skip.test.ts) | Skip stays enabled while Test or a readiness refresh is still waiting and completes before the probe answers; a probe answer that arrives after Skip or Continue is dropped; a probe that fails while the user waits is still reported. A former model's late response/error cannot overwrite a newly selected model's test (a characterization: the test-step exits already retired the probe). Test probes the selected path and never the active profile in its place: an unsaved choice asks for a profile instead, and with no path the active profile is selected first. Editing a saved local model's name makes the choice unsaved again, so Test cannot measure the old model under the new name. The step rail marks done steps and moves to the step pressed. |
