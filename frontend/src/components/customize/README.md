# frontend/src/components/customize

[中文说明](README_zh.md)

F-19 Customize modal. Nine tab components, a nested editor overlay, and `vendors/` cards. Class names (`#cust`, `.cust-tab`, `.prof-row`, `.cust-row`, `.toggle`) match the E2E contract. Tab unmount disposes the timer lease.

## Files

| File | Responsibility |
| --- | --- |
| [`ComputeTab.tsx`](ComputeTab.tsx) | Compute, remote GPU, jobs. Shows what Python and R run in for the open session (or the defaults): environment name, kind (built-in / managed / local) and version, plus whether R's key packages load, read from `runtimes` on the environment listing. The tracked-package row lists installed versions and what is missing. An install's outcome stays on screen: the version installed, the environment it went into and what a running kernel must do. Adding or removing a remote host and submitting or cancelling a job answer under their own form, never on the status line behind the dialog (SCI-04). With no local GPU the GPU row says what fails and that nothing substitutes an approximation, and an "Other remote compute" row names NVIDIA NIM (keys in the daemon's environment, nothing to set up here) and `openai4s cluster` for Slurm, with a link to docs/compute.md; a team member sees neither pointer (SCI-18). Under the host picker the tab says what Add does before it is clicked -- the exact read-only `ssh … nvidia-smi` check (`remoteProbeCommand`), what the host needs, that services are set up later through ssh steps under the permission rules, where the list is kept and that Remove changes nothing on the host; Add stays disabled until a host is picked and says when the check found no GPU (SCI-19). Install and Run are disabled while their field is empty (SCI-05). One job poll chain, 1500ms on the lease; a newer read supersedes an older one. The readiness card is onboarding's `EnvironmentCard`; the status comes from send's `refreshEnvironmentStatus`. |
| [`ComputeTab.test.tsx`](ComputeTab.test.tsx) | The Python and R rows name environment, kind and version and say which R packages load; the package row carries versions; an install's result (with version) and a failed install's reason stay on screen. Add explains its check, waits for a host, and an unreachable result is said beside the form (SCI-19). Add, Install and Run stay disabled while their field is empty (SCI-05). |

| [`SkillsTab.tsx`](SkillsTab.tsx) | Personal / project / collection skills. A search box ranks every skill, collection members included, the way the `/` picker does (name, description, Chinese keyword, declared domain), and reaches a collection by its own name ("bioskills", "bio skills"): the collection row shows above the hits and expands, and the count line says how many hits sit inside a collection (`searchSkillCatalog`, SCI-09); a `host_only` skill is marked with the number of domains it limits a session to and, on expand, says what loading it does for the rest of the session: limited to the listed domains, or -- with none declared -- network turned off, and that a new session is the way back (SCI-07). A Skill that cannot run here says why in words, and offers "Open Compute" when a remote GPU or a package install is the fix (SCI-08). The name opens the row: the whole description (`full_description` from `GET /skills/{name}`), what it needs and its network mode in words, and SKILL.md rendered (`renderMd`, no external resources); "Use in chat" is a labelled button (SCI-06). |
