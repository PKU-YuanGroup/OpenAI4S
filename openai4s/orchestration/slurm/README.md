# `openai4s/orchestration/slurm/`

The Slurm backend — **the only place in the tree allowed to name a scheduler**. INV-2 is a claim about the orchestration core, not a claim that no code anywhere may know how jobs are submitted; something has to. Concentrating that knowledge in one directory is what makes the rule checkable: the leak guard skips this path by name, so anything scheduler-shaped *outside* it is a defect rather than a judgement call.

| file | what it is |
|---|---|
| [`__init__.py`](__init__.py) | Re-exports the backend, the broker and the cluster config. Imported by composition code; the orchestration core never reaches it. |
| [`backend.py`](backend.py) | The `AllocationBackend` implementation, and the state table that turns `TIMEOUT` into `(FAILED, TIME_LIMIT_EXCEEDED)`. Three behaviours are load-bearing rather than incidental. A lost submission is `Unknown`, never a failure — and `submit` begins by asking whether the token is already out there, so the retry after an `Unknown` returns `Existing` instead of putting a second job on the cluster (INV-8). A job in neither the queue nor accounting is `LOST`, never `COMPLETED`: claiming success for work we cannot find is the one answer that silently loses science. And an unreachable scheduler leaves the phase where it was — a cluster outage must not terminate everyone's jobs. |
| [`broker.py`](broker.py) | The subprocess boundary: every `sbatch`/`squeue`/`sacct`/`scancel` call and all the parsing, so INV-9 is checkable in one place. argv is a list with `shell=False`, so a profile named `gpu; rm -rf /` is an argument rather than a command; job names and comments are additionally restricted to a character class, because those two fields carry our identifiers *into* scheduler output and back out through a parser. A credential-shaped environment variable is refused outright — a secret travels as the path to an 0600 file. `SlurmCommandError` distinguishes `timed_out` from `unreachable` from a plain refusal; writing the tests proved why, since swallowing "no scheduler on PATH" as "no such job" declared every running job lost. |
| [`profiles.py`](profiles.py) | `cluster.toml`: the one file that maps a profile name a scientist says (`gpu-interactive`) onto the partition and QoS an administrator controls (D5). `ClusterProfile.public()` is the admin-readable view and deliberately omits both — a queue name in a JSON body is the same leak by a slower route. Parsed with `tomllib` where it exists and with a deliberately tiny fallback where it does not: `requires-python` is 3.10, CI runs 3.10, and a tomllib-only reader would have made the whole cluster feature dead on the floor version. The fallback understands tables, strings, integers and booleans, and **refuses** anything else with a line number rather than guessing — failing to read is recoverable, misreading schedules onto the wrong queue. |
